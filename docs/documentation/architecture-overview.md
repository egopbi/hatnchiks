# Архитектурный обзор Hatnchiks

## 1. Высокоуровневое описание
- **Назначение сервиса**: REST API для пати-игры «Шляпа». Управляет регистрацией пользователей, созданием и запуском игр, выдачей карточек и состоянием раундов.
- **Технологический стек**: Python 3.12, FastAPI, Pydantic, SQLAlchemy (async), Redis (async), FastAPI Users, Loguru, Uvicorn.
- **Общая структура**: монолитное FastAPI-приложение, разделённое на модули `api`, `backend`, `auth`, `dependencies`, `models`, `schemas`, `utils`, `tests`.  
  Бизнес-логика сосредоточена в сервисах `GameService`/`HatService` и Redis-репозиториях.

## 2. Слои и зависимости
| Слой | Назначение | Основные пакеты |
| --- | --- | --- |
| **Interface (HTTP)** | Обработчики запросов, схемы ответов, зависимостей FastAPI. | `src/api`, `main.py` |
| **Application / Services** | Управление игровыми сценариями, orchestration между инфраструктурой и доменом (частично). | `src/backend/game_services.py`, `src/backend/database.py` |
| **Infrastructure** | Адаптеры БД, Redis, интеграции. | `src/backend/redis.py`, `src/backend/database.py`, `src/backend/abstractclasses.py` |
| **Auth** | Аутентификация и менеджер пользователей. | `src/auth/**`, `src/dependencies/authentication/**` |
| **Domain (зарождающийся)** | Модели SQLAlchemy, схемы Pydantic. | `src/models/**`, `src/schemas/**` |
| **Shared / Utils** | Логирование, декораторы, исключения. | `src/utils/**`, `src/exceptions.py` |

Зависимости направлены сверху вниз (interface → services → infrastructure). Обратные ссылки присутствуют (например, API напрямую обращается к Redis-адаптерам), что учитывается в плане модернизации.

## 3. Карта модулей
- `main.py` — точка входа FastAPI, инициализация приложения, lifespan-хук для graceful shutdown БД.
- `src/api/` — четыре модуля:
  - `users.py` — регистрация/логин/профиль пользователя.
  - `games.py` — создание, запуск, удаление игр, просмотр списков игр.
  - `cards.py` — CRUD-операции над карточками игры.
  - `game_process.py` — действия в ходе раунда (вытягивание карточки, переход к следующему раунду).
- `src/backend/game_services.py` — бизнес-логика игры (`GameService`, `HatService`), работа с репозиториями.
- `src/backend/redis.py` — адаптеры Redis (`GameRedisRepository`, `HatRedisRepository`, `ProjectRepository`).
- `src/backend/database.py` — коннектор SQLAlchemy и сервис `DatabaseService` для операций с пользователями (Postgres).
- `src/auth/**` — JWT, хеширование паролей, менеджер пользователей FastAPI Users.
- `src/dependencies/**` — провайдеры зависимостей FastAPI (БД, авторизация, юзеры).
- `src/models/**` — SQLAlchemy-модели (пока покрывает только пользователей).
- `src/schemas/**` — Pydantic-схемы запросов/ответов (игровые сущности, токены, пользователи).
- `src/utils/**` — логгеры, декораторы (перезагрузка данных игры, проверка старта, обработка ошибок БД).
- `tests/**` — pytest-пакеты с базовыми тестами API (`tests/test_api/test_games.py`).

## 4. Жизненный цикл запросов
1. **HTTP-вход** (FastAPI): маршрутизатор в `src/api/__init__.py` подключает тематические роутеры.
2. **Зависимости**: через `Depends` подмешиваются экземпляры `GameService`, `DatabaseService`, валидация пользователей, формы.
3. **Сервисы**: обработчики вызывают методы `GameService`/`HatService` (для игры) или `DatabaseService` (для пользователей).
4. **Инфраструктура**:
   - Redis (`GameRedisRepository`, `HatRedisRepository`) хранит активные игры, карточки, «шляпу», параметры игры.
   - SQLAlchemy (через `DatabaseService`) работает с таблицей `users` в Postgres (модели `src/models/user.py`).
5. **Сериализация**: ответы возвращаются как JSON через Pydantic-схемы или словари.

## 5. Персистентность и данные
- **PostgreSQL / SQLAlchemy**: используется для хранения пользователей. Настройки берутся из `config.py` (класс `DbSettings`). Naming convention задаётся через `settings.db.naming_conventions`.
- **Redis**: основное состояние игры (карточки, раунды, таймеры, активные игры) находится в Redis. Используются структуры `list`, `set`, `string`.
- **Миграции**: предполагается Alembic (по `alembic.ini`), но миграции отсутствуют; таблицы необходимо создавать вручную или генерацией миграций.

## 6. Аутентификация и пользователи
- JWT-стратегия через FastAPI Users (`src/dependencies/authentication/backend.py`).
- Ключи JWT читаются из файлов `sensitive/jwt/*.pem`.
- `UserManager` (`src/auth/user_manager.py`) расширяет `BaseUserManager` и переопределяет хуки логирования.
- Пароли хешируются через bcrypt (`src/auth/password_check.py`).
- В настоящее время `users.py` комбинирует собственную авторизацию и зачатки FastAPI Users; часть зависимостей не завершена (например, `get_current_auth_user`).

## 7. Игровой процесс
- **GameService**: управляет параметрами игры (команды, таймер, раунды), обеспечивает запуск и переходы раундов.
- **HatService**: работает с «шляпой» (карточки раундов) через Redis, выполняет перемешивание, перемещение карт между основным и вторым списками.
- **Декораторы**:
  - `@check_for_game_start` — проверяет, что игра была запущена (наличие параметров в Redis).
  - `@reloader` — при `NeedToReloadInfo` перезагружает настройки игры из Redis и переисполняет операцию.
- **Исключения** в `src/exceptions.py` сигнализируют о доменных ошибках (нет карточки, шляпа пуста, раунды закончились и т. п.).

## 8. Логирование и мониторинг
- Логирование реализовано через Loguru (`src/utils/logger.py`).
- Логи пишутся в stdout и файлы `logs/backend.log`, `logs/database.log`.
- Создание каталога логов происходит в рантайме (`os.makedirs("src/logs", exist_ok=True)`), при этом отдельный каталог `logs/` используется для файлов (следует выровнять поведение при модернизации).
- Отсутствуют встроенные health-check, метрики и трассировка; учтено в дорожной карте модернизации.

## 9. Конфигурация
- `config.py` использует `pydantic-settings` и `.env`.  
  Доступны секции:
  - `db` (`DbSettings`) — строка подключения и echo-флаг.
  - `rd` (`RdSettings`) — параметры Redis.
  - `auth.jwt` (`AuthJWT`) — пути к ключам, алгоритм, время жизни токена.
  - `access_token` (`AccessToken`) — секреты для токенов восстановления/верификации.
- Файлы секретов ожидаются в `sensitive/jwt/` (путь исключён `.gitignore`).

## 10. Тестирование
- Покрытие тестами ограничено модулем `tests/test_api/test_games.py`.
- Тесты используют `httpx.AsyncClient` с `ASGITransport` для интеграционного тестирования API без поднятия сервера.
- Базы данных/Redis в тестах не мокируются; требуется живая инфраструктура или дополнительная настройка окружения.

## 11. Известные ограничения
- Доменная модель распределена по слоям без явных границ; отсутствуют явные агрегаты и события.
- Зависимость API от конкретных реализаций репозиториев ограничивает расширяемость (например, Postgres-режим для `HatService` не реализован).
- Отсутствует схема БД для игровых сущностей — их хранение в Redis затрудняет аналитические запросы.
- Недостаточно обработаны сценарии ошибок (многие обработчики возвращают 200 даже при проблемах, нет единообразного формата ошибок).
- Не завершена интеграция FastAPI Users (часть зависимостей/роутеров не используется).
- Нет документации по развёртыванию и запуску в production-среде.
