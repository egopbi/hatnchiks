# Инварианты качества, границы редактирования и тестирование

## 1. Инварианты качества

* **Статический анализ:** линтер без ошибок. Рекомендуемые команды:

  ```bash
  uv run ruff check
  ```
* **Форматирование:** форматирование кода обязательно:

  ```bash
  uv run ruff format
  ```
* **Архитектурные слои:** не нарушать направление зависимостей `domain → application → infra`. Обратные связи запрещены.
* **Именование/логи/ошибки:** следовать принятому стилю проекта (PEP8/Google-style). Исключения — узкие, без `bare except:`. Логгирование по уровням (`DEBUG/INFO/WARN/ERROR`), без заглушки ошибок.

## 2. Границы редактирования

* Менять **только** то, что необходимо для достижения цели задачи.
* Не перемещать большие блоки кода без веской причины.
* Не переименовывать публичные символы/контракты без явного требования.
* Комментарии и докстринги добавляются рядом с изменённым кодом; не переписывать существующие без необходимости.

## 3. Тестирование

### 3.1 Что покрывать

* Новые ветви выполнения и граничные случаи.
* Регрессии по обнаруженным багам (минимум один регрессионный тест на багфикс).
* Стабильность публичных контрактов (API, схемы данных).

### 3.2 Размещение тестов

* Рядом с кодом модуля или в общем каталоге `tests/` — согласно принятому паттерну проекта.

### 3.3 Шаблон тест-кейса (pytest, пример)

```python
def test_parse_user_without_email_returns_none():
    user = {"name": "Ann"}
    assert parse_user(user).email is None
```

### 3.4 Запуск тестов

```bash
uv run pytest -q
```

### 3.5 Политика snapshot-тестов

* Если снапшот изменился — в описании PR указать причину и обоснование изменения артефакта.

## 4. Минимальный дифф

* Каждый PR должен содержать **минимально необходимый** набор правок.
* Не выполнять «проездом» несвязанные улучшения — выносить в отдельные задачи/PR.

## 5. Контрольный список качества перед PR

* [ ] `ruff format` и `ruff check` пройдены.
* [ ] Тесты добавлены/обновлены; запуск `pytest -q` зелёный.
* [ ] Архитектурные слои не нарушены.
* [ ] Публичные контракты не изменены без явной необходимости.
* [ ] Дифф минимален и локализован.
