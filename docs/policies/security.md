# Правила безопасности, ограничения и эскалация

## 1. Доступ к файлам и путям

* **Разрешено:** читать/редактировать **только** пути, не попадающие под `.gitignore`.
* **Запрещено:** любые операции над игнорируемыми путями (артефакты, кэши, секреты, локальные конфиги), а также создание новых файлов в игнорируемых директориях.
* **Проверка перед записью (алгоритм):**

  1. Прочитать `.gitignore` и вычислить итоговый набор паттернов.
  2. Для каждого изменяемого пути выполнить сопоставление (аналог `git check-ignore`).
  3. Если путь игнорируется — **отклонить изменение** и зафиксировать причину в отчёте.

## 2. Секреты и персональные данные

* Никогда не читать/писать референсы на секреты: значения переменных окружения, токены, ключи.
* Не добавлять секреты в код/конфиги/логи/коммиты/PR.
* При обнаружении секрета: **немедленно остановить работу**, создать задачу
  *“Обнаружен секрет в `<path>`: требуется ротация и удаление из истории”*.

## 3. Исполнение кода и сеть

* Не запускать произвольные команды/скрипты, кроме явно разрешённых инструментов проекта.
* Не обращаться в интернет. Скачивание зависимостей допускается **только** согласно lock-файлам.
* Любые генерации данных и операции, влияющие на прод-состояние, **запрещены** без явного чек-листа и `ALLOW_MIGRATIONS=true`.

## 4. Зависимости и миграции БД

* Обновление/добавление зависимостей — только с lock-файлом; версии фиксировать политикой проекта (`~=`/`^`).
* Миграции по умолчанию **запрещены**. Если `ALLOW_MIGRATIONS=true`:

  * миграции атомарные и обратимые;
  * выносятся отдельным коммитом;
  * выполняются не в основном пайплайне, а в job проверки миграций.

## 5. Запрещённые действия

* Изменять/добавлять файлы, подпадающие под `.gitignore`.
* Переписывать историю git.
* Массовые переименования/реформат без явной задачи.
* Изменения, влияющие на лицензию/брендинг/авторские права.
* Интеграции, требующие внешних ключей/сетевого доступа, без явного разрешения.

## 6. Эскалация и остановка

При нарушении жёстких правил (секрет, `.gitignore`, миграция без разрешения):

1. **Немедленная остановка**.
2. Создать отчёт `reports/STOP-YYYYMMDD-HHMMSS.md` с описанием причины и контекстом.
3. Коммит/PR **не** формировать.
4. Уведомить ответственных (в тикете/PR-обсуждении/канале разработки).

## 7. Чек-лист безопасности перед коммитом

* [ ] Все изменённые пути проверены против `.gitignore`.
* [ ] В диффе нет секретов, токенов, ключей, конфиденциальных данных.
* [ ] Зависимости обновлены только с использованием lock-файла.
* [ ] Миграций нет, либо миграции оформлены согласно правилам §4.
* [ ] Логи и сообщения коммитов не содержат чувствительных данных.
* [ ] Документация обновлена, если правила безопасности затронуты.
