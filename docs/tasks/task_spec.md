# Спецификация входной задачи для агента

## Назначение

Единый формат входного задания (Task Spec), по которому агент планирует изменения, ограничивает скоуп и проверяет результат.

## Минимально необходимые поля

```json
{
  "id": "TASK-xxx",
  "title": "Короткое название",
  "goal": "Что должно измениться для пользователя/API/системы",
  "acceptance_criteria": ["Проверяемые условия приёмки (тесты/эндпоинты/сообщения)"],
  "change_type": "bugfix|feature|refactor|docs|chore",
  "constraints": ["Запреты и инварианты (не менять публичные API, совместимость Py3.12)"],
  "affected_paths": ["пути/**", "которые/**", "меняем/**"],
  "forbidden_paths": ["generated/**", "scripts/local/**", "и_прочее/**"]
}
```

### Поля — пояснения

* **id** — связь с тикет-трекером, помогает трассировать коммиты/PR/релизы.
* **title** — краткое описание сути изменения.
* **goal** — целевой эффект (не реализация), формулируется от лица потребителя.
* **acceptance_criteria[]** — измеримые условия успеха (конкретные тесты, статусы HTTP, сообщения ошибок).
* **change_type** — влияет на стратегию (например, для `bugfix` — минимальный дифф + регресс-тест).
* **constraints[]** — жёсткие ограничения (интерфейсы, совместимость, SLA, производительность).
* **affected_paths[]** — где разрешены правки (ускоряет индексацию и снижает риск побочки).
* **forbidden_paths[]** — жёсткое «нельзя» (совместно с `.gitignore` повышает безопасность).

## Полезные дополнения (опционально)

```json
{
  "examples": {
    "input": "Пример запроса/входных данных",
    "output": "Ожидаемый ответ/артефакт"
  },
  "non_goals": ["Что сознательно не решаем в этой задаче"],
  "perf_budget": {"p95_ms": 120},
  "flags": {"ENABLE_HAT_EXPERIMENTAL_FLOW": false}
}
```

## Пример заполнения

```json
{
  "id": "TASK-123",
  "title": "Fix hat round overflow",
  "goal": "После завершения 3-го раунда игроки не могут тянуть карточки.",
  "acceptance_criteria": [
    "При попытке тянуть в 4-м раунде API возвращает 400 и сообщение 'game finished'",
    "pytest tests/test_api/test_games.py::TestAPIGames::test_post_create_game проходит"
  ],
  "change_type": "bugfix",
  "constraints": [
    "Нельзя менять публичные API в пакете src.backend",
    "Совместимость с Python 3.12"
  ],
  "affected_paths": ["src/backend/**", "tests/test_api/**"],
  "forbidden_paths": ["generated/**", "scripts/local/**"],
  "examples": {
    "input": "POST /games/{game_id}/cards {\"user_id\": \"user-1\", \"text\": \"Шерлок Холмс\"}",
    "output": "{\"success\": true, \"message\": \"Card 'card-xxxxx' was added\"}"
  }
}
```

## Мэппинг на процесс и CI

* Поля `acceptance_criteria[]` маппятся на шаги CI (конкретные тесты/команды).
* `affected_paths[]` ограничивает индексацию и выбор файлов для диффа.
* `constraints[]` и `forbidden_paths[]` проверяются до применения изменений.

## Ошибки и допущения

* Если какое-то поле отсутствует, агент формирует **явные допущения** и фиксирует их в разделе PR «Почему так».
* При конфликте критериев приёмки — агент останавливается и просит уточнение либо формирует STOP-отчёт.
