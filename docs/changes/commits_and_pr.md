# Коммиты и Pull Request

## 1. Правила сообщений коммитов (Conventional Commits)

**Формат:**

```
<type>(<scope>): <short summary>

Body:
- Problem: <в чём была проблема>
- Solution: <как решено>
- Trade-offs: <что ухудшили/на что согласились>

Refs: #<issueId> TASK-<id>
```

**Поддерживаемые `type`:** `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `chore`, `ci`
**`scope` (пример):** `game`, `parser`, `api`, `infra`, `db`, `auth`

**Примеры:**

* `fix(parser): handle missing email in parse_user()`
* `feat(game): reset round state after finish`
* `test(api): add regression for hat overflow`

## 2. Шаблон описания PR

**Заполнять в каждом PR.**

```
### Задача
TASK-123 — Fix hat round overflow

### Изменения (по файлам/участкам)
- src/parser.py: добавлена проверка email
- tests/test_parser.py: добавлен регрессионный тест

### Почему так
Краткое обоснование архитектурных/алгоритмических решений; альтернативы и причины отказа.

### Риски и план отката
- Риск: возможен сбой при пустом поле X
- Откат: revert коммита <sha>, перезапуск сервиса

### Чек-лист автора
- [ ] Пути не подпадают под `.gitignore`
- [ ] Формат/линт/типы/тесты пройдены
- [ ] Изменены только необходимые строки (минимальный дифф)
- [ ] Документация обновлена (README/docs/CHANGELOG)
- [ ] Изменения снапшотов (если есть) обоснованы
```

## 3. Требования к содержанию PR

* **Минимальный дифф:** без «проездом» улучшений, не связанных с задачей.
* **Тесты:** для bugfix — регресс-тест; для feature — позитив/негатив + границы.
* **Документация:** обновить `README.md`, `CHANGELOG.md`, `docs/**` при изменении публичного поведения.
* **Ссылки:** на тикет/обсуждение/дизайн-док (если есть).
* **Снапшоты:** любые изменения — с явным пояснением причин.

## 4. CHANGELOG

* Помечать **ломающие изменения** префиксом `BREAKING:` и кратким описанием.
* Группировать по версиям/датам: `Added`, `Changed`, `Fixed`, `Removed`.

## 5. Политика ревью

* Ревьюер проверяет: соответствие задаче, минимальность диффа, тесты, безопасность (секреты, `.gitignore`), соблюдение слоёв архитектуры.
* Разрешено требовать разбиение PR, если изменения затрагивают разные слои/темы.
* Разрешено блокировать PR до появления регресс-тестов или обновления документации.

## 6. Быстрый чек-лист перед отправкой PR

* [ ] Conventional Commit(ы) оформлены корректно
* [ ] PR-шаблон заполнен полностью
* [ ] Все проверки локально зелёные: `ruff format`, `ruff check`, `mypy/pyright/tsc`, `pytest -q`
* [ ] Обновлены `docs/**` и `CHANGELOG.md` при изменении публичного поведения
* [ ] Нет изменений в путях из `.gitignore`
* [ ] Дифф минимален; без массовых переименований/реформатинга вне цели задачи
